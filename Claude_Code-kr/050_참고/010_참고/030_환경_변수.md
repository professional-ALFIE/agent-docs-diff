# 환경 변수

> Claude Code 동작을 제어하는 환경 변수에 대한 참고 자료입니다.

환경 변수는 모델 선택, 인증, 요청 라우팅 및 기능 토글과 같은 Claude Code 동작을 제어할 수 있습니다. 동일한 동작의 대부분은 [설정 파일](/docs/ko/settings) 필드, [CLI 플래그](/docs/ko/cli-reference) 또는 `/model`과 같은 세션 내 명령을 통해서도 구성할 수 있습니다.

이 페이지에서는 다음을 다룹니다:

* [환경 변수 설정](#set-environment-variables) 방법 (셸 또는 설정 파일에서)
* [동작을 설정할 수 있는 방법이 여러 개일 때 어떤 값이 적용되는지](#precedence) 확인
* [Claude Code가 읽는 변수 조회](#variables)
* [변수가 기능 플래그 가져오기를 끄면 어떤 기능이 작동을 멈추는지](#features-that-need-feature-flag-fetching) 확인

<h2 id="set-environment-variables">
  환경 변수 설정
</h2>

셸에서 설정한 변수는 해당 터미널 세션 동안만 유지되며, 설정 파일의 변수는 `claude`가 실행될 때마다 적용됩니다.

<h3 id="in-your-shell">
  셸에서
</h3>

`claude`를 실행하기 전에 변수를 설정합니다:

<Tabs>
  <Tab title="macOS, Linux, WSL">
    ```bash theme={null}
    export API_TIMEOUT_MS="1200000"
    claude
    ```

    모든 세션에서 설정하려면 `~/.bashrc`, `~/.zshrc` 또는 셸의 프로필 파일에 `export` 줄을 추가합니다.
  </Tab>

  <Tab title="Windows PowerShell">
    ```powershell theme={null}
    $env:API_TIMEOUT_MS = "1200000"
    claude
    ```

    모든 세션에서 설정하려면 `[Environment]::SetEnvironmentVariable("API_TIMEOUT_MS", "1200000", "User")`를 실행하고 새 터미널을 엽니다.
  </Tab>

  <Tab title="Windows CMD">
    ```batch theme={null}
    set API_TIMEOUT_MS=1200000
    claude
    ```

    모든 세션에서 설정하려면 `setx API_TIMEOUT_MS "1200000"`을 실행하고 새 터미널을 엽니다.
  </Tab>
</Tabs>

할당 줄은 성공 시 아무것도 출력하지 않으므로, `claude`를 실행하기 전에 같은 셸에서 변수를 출력하여 설정되었는지 확인합니다:

<Tabs>
  <Tab title="macOS, Linux, WSL">
    ```bash theme={null}
    echo $API_TIMEOUT_MS
    ```
  </Tab>

  <Tab title="Windows PowerShell">
    ```powershell theme={null}
    echo $env:API_TIMEOUT_MS
    ```
  </Tab>

  <Tab title="Windows CMD">
    ```batch theme={null}
    echo %API_TIMEOUT_MS%
    ```
  </Tab>
</Tabs>

<h3 id="in-settings-files">
  설정 파일에서
</h3>

`settings.json` 파일의 `env` 키 아래에 변수를 추가하고, 파일이 없으면 생성합니다. Claude Code는 파일에서 직접 읽으므로 `claude`가 어떻게 실행되었는지와 관계없이 적용됩니다. 실행 중인 세션은 파일을 저장할 때 새로운 값과 변경된 값을 환경에 적용하지만, [OpenTelemetry 모니터링](/docs/ko/monitoring-usage)과 같이 시작 시 변수를 한 번만 읽는 기능은 다시 실행할 때까지 시작 값을 유지합니다. 파일에서 변수를 제거해도 실행 중인 세션에서 설정 해제되지 않으며, 제거는 다음 번 `claude`를 실행할 때 적용됩니다.

```json ~/.claude/settings.json theme={null}
{
  "env": {
    "API_TIMEOUT_MS": "1200000",
    "BASH_DEFAULT_TIMEOUT_MS": "300000"
  }
}
```

선택한 파일은 변수가 적용되는 대상을 제어합니다:

| 파일                            | 적용 대상                                                                          |
| :---------------------------- | :----------------------------------------------------------------------------- |
| `~/.claude/settings.json`     | 모든 프로젝트에서 사용자                                                                  |
| `.claude/settings.json`       | 소스 제어에 체크인된 프로젝트에서 작업하는 모든 사람                                                  |
| `.claude/settings.local.json` | 이 프로젝트에서만 사용자, Claude Code가 설정을 저장할 때 gitignored됨; 직접 생성하는 경우 gitignore에 추가합니다 |
| 관리되는 설정                       | 관리자가 배포한 조직의 모든 사람                                                             |

각 파일이 있는 위치는 [설정 파일](/docs/ko/settings#where-settings-live)을 참조하고, 둘 이상이 같은 변수를 설정할 때 결합되는 방식은 [설정 우선순위](/docs/ko/settings#settings-precedence)를 참조합니다.

<h2 id="precedence">
  우선순위
</h2>

일부 동작은 환경 변수와 전용 설정 키 모두를 가지고 있으며, Claude Code가 어느 것을 먼저 읽는지는 키마다 다릅니다. `ANTHROPIC_MODEL`과 `CLAUDE_CODE_AUTO_CONNECT_IDE`의 경우, Claude Code는 변수를 먼저 읽고 변수가 설정되지 않았을 때만 `model` 또는 `autoConnectIde` 설정을 사용합니다. 설정하려는 쌍의 경우, 아래의 변수 행과 [설정 참조](/docs/ko/settings-reference)의 키 항목을 확인하십시오.

동일한 변수가 셸과 설정 파일 `env` 블록 모두에 설정된 경우, 설정 파일 값이 적용됩니다. Claude Code는 각 `env` 항목을 프로세스 환경에 기록하여 셸에서 상속된 값을 대체합니다. [`env` 설정](/docs/ko/settings-reference#when-claude-code-applies-env-values)은 언제 적용되는지를 나타냅니다. 몇 가지 변수는 특별하게 처리됩니다. [`env` 설정](/docs/ko/settings-reference#env)은 예외를 나열합니다.

설정 파일에서 변수를 설정할 수 있지만 제거할 수는 없습니다. 제어하지 않는 셸 프로필에서 내보낸 `CLAUDE_CODE_USE_VERTEX`와 같이 설정 해제할 수 없는 변수를 재정의하려면, `env` 블록에서 빈 문자열로 설정하십시오: `"CLAUDE_CODE_USE_VERTEX": ""`. Claude Code는 빈 값을 공급자 선택을 위해 설정 해제된 것으로 취급합니다. 하위 프로세스는 여전히 빈 값을 상속합니다.

설정 파일 간에 `env` 값은 [설정 우선순위](/docs/ko/settings#settings-precedence)를 따르므로, 관리되는 설정 항목이 사용자 또는 프로젝트 설정의 동일한 변수를 재정의합니다.

환경 변수가 CLI 플래그 및 세션 내 명령과 상호 작용하는 방식은 기능마다 다릅니다: `--model`과 `/model`은 `ANTHROPIC_MODEL`을 재정의하고, `CLAUDE_CODE_EFFORT_LEVEL`은 `--effort`와 `/effort`를 재정의합니다. 변수가 다른 구성 소스와 상호 작용할 때, [변수](#variables) 목록의 해당 행은 우선순위를 나타내거나 이를 문서화하는 페이지로 연결됩니다.

Claude Code는 시작 시 셸 환경 변수를 읽으므로, 이에 대한 변경 사항은 다음에 `claude`를 시작할 때 적용됩니다. 설정 파일의 `env` 키 아래에 설정된 변수는 파일이 변경될 때 실행 중인 세션에 다시 적용되며, [설정 파일에서](#in-settings-files)에 설명된 시작 전용 예외가 있습니다.

<h2 id="variables">
  변수
</h2>

숫자 변수(예: 타임아웃, 토큰 예산, 재시도 횟수)는 일반 숫자 외에도 과학 표기법과 숫자 구분 기호 표기법을 허용합니다. 단, 변수의 행에서 일반 숫자만 사용한다고 명시한 경우는 제외됩니다. 예를 들어 Claude Code는 `2e3`을 2000으로, `64_000`을 64000으로 읽습니다. v2.1.211 이전에는 이러한 표기법이 타임아웃을 1로 설정하는 `1e6`과 같이 훨씬 작은 값을 자동으로 설정할 수 있었습니다.

<Note>
  동작을 켜거나 끄는 변수의 경우, `1` 또는 `true`를 설정하여 켜고 `0` 또는 `false`를 설정하여 끕니다(대소문자 구분 없음).

  일부 변수는 설정 여부만 읽으므로, `0`을 포함한 모든 비어있지 않은 값이 동작을 켜고, 변수를 설정 해제하거나 빈 값으로 설정하여 동작을 끕니다. 이러한 변수들은 다음과 같습니다:

  * `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`
  * `DISABLE_TELEMETRY`
  * `DISABLE_ERROR_REPORTING`
  * `CLAUDE_CODE_TMUX_TRUECOLOR`
  * `FALLBACK_FOR_ALL_PRIMARY_MODELS`
  * `IS_DEMO`

  다른 하나의 변수는 자체 규칙을 가집니다: `FORCE_HYPERLINK`는 숫자를 읽으므로 `0`만 끕니다. 각 변수의 행에도 자체 규칙이 명시되어 있습니다.
</Note>

<h2 id="features-that-need-feature-flag-fetching">
  기능 플래그 가져오기가 필요한 기능
</h2>

Claude Code는 Anthropic에서 가져오는 기능 플래그를 통해 일부 기능을 활성화합니다. Claude Code는 다음 세션에서 해당 가져오기를 건너뜁니다:

* `DISABLE_GROWTHBOOK`, `DISABLE_TELEMETRY`, `DO_NOT_TRACK` 또는 `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`을 설정한 세션; [변수 테이블](#variables)의 각 변수 행에서 어떤 값이 가져오기를 비활성화하는지 나타냅니다
* Amazon Bedrock, Claude Platform on AWS, Google Cloud의 Agent Platform 또는 Microsoft Foundry와 같은 [타사 제공자](/docs/ko/third-party-integrations)의 세션(Claude Code를 포함하는 호스트 플랫폼이 `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST`를 설정하지 않은 경우)
* [Claude 앱 게이트웨이](/docs/ko/claude-apps-gateway) 세션

가져오기가 비활성화된 경우 다음을 수행할 수 없습니다:

* Pro, Max 및 Team 플랜에서 [기본적으로 자동 모드로 세션 시작](/docs/ko/permission-modes#which-mode-a-session-starts-in)
* VS Code 확장이 [시작 권한 모드에 대한 설정 파일 읽기](/docs/ko/permission-modes#switch-permission-modes)
* [`/auto-mode-setup`](/docs/ko/auto-mode-config#generate-environment-entries)을 실행하여 `autoMode.environment` 항목 작성
* [원격 제어](/docs/ko/remote-control#requirements) 사용
* [이 머신을 넘어 세션에 메시지 전송](/docs/ko/cross-session-messaging#message-sessions-on-other-machines); 이 머신의 세션 간 메시징은 가져오기가 비활성화된 상태에서 작동합니다
* [`claude import` 또는 `/import` 명령 실행](/docs/ko/cli-reference#cli-commands)
* [`/skill-doctor`](/docs/ko/skills#find-unused-skills) 실행 또는 `/plugin` **Stats** 탭에서 보고서 열기
* [어드바이저 도구](/docs/ko/advisor#requirements) 사용
* [아티팩트의 댓글](/docs/ko/artifacts#collect-comments-on-an-artifact) 읽기 또는 답글 달기
* `MCP_SDK_GENERATION` 및 `MCP_PROTOCOL_NEGOTIATION`을 설정하지 않고 [v2 MCP 클라이언트 런타임](/docs/ko/mcp#mcp-client-runtimes) 및 해당 프로토콜 프로브 가져오기; Claude Code는 `MCP_SDK_GENERATION=v2`를 설정하지 않으면 v1 런타임을 사용하고, `MCP_PROTOCOL_NEGOTIATION=auto`를 설정하지 않으면 프로브를 건너뜁니다
* Git Bash가 설치된 Windows의 claude.ai 및 Console 계정에 대해 기본적으로 [PowerShell 도구](/docs/ko/tools-reference#powershell-tool) 가져오기; Claude Code는 `CLAUDE_CODE_USE_POWERSHELL_TOOL=1`을 설정하지 않으면 Git Bash를 통해 셸 명령을 라우팅합니다. Git Bash가 없는 Windows에서는 도구가 활성화된 상태로 유지됩니다
* [Claude가 작성한 피드백](/docs/ko/tools-reference#sendfeedback-tool-behavior) 가져오기(Claude Code는 가져온 플래그를 통해 활성화)
* Claude Code가 [API가 거부할 입력 스키마를 가진 MCP 도구 제외](/docs/ko/mcp#tools-with-invalid-input-schemas); 스키마를 어쨌든 전송하고, 이를 포함하는 요청은 [도구를 위치로 이름 지정하는 400 오류](/docs/ko/errors#tool-input-schema-is-invalid)로 실패합니다

<h3 id="first-session-after-an-install-or-upgrade">
  설치 또는 업그레이드 후 첫 번째 세션
</h3>

Claude Code를 설치한 후 또는 기능을 추가하는 버전으로 업그레이드한 후 첫 번째 세션에서 [플래그 게이트된 기능](#features-that-need-feature-flag-fetching)이 누락될 수 있으며, 세션은 자동 모드로 시작하는 플랜에서 수동 모드로 시작할 수 있습니다. Claude Code는 해당 세션 중에 플래그를 가져오므로 다음 세션에서 둘 다 있습니다.

새로 설치한 후 `claude -p`, Agent SDK 또는 VS Code 확장과 같은 비대화형 세션에서 Claude Code는 [시작 권한 모드를 선택](/docs/ko/permission-modes#which-mode-a-session-starts-in)하기 전에 플래그를 선택할 수 있습니다.
